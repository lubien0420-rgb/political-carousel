# 검수 규칙

입력: `data/research/<폴더>/` 의 copy.json · factsheet.json · pack.md
절차:
1. `python scripts/review.py <폴더>` → 기계 검증(팩트시트·카피) + 위험 표현 점검 + 문장 목록(`review_input.md`)
2. 검수자가 아래 체크리스트로 `review.json` 작성 — **카피 작성자와 다른 시각으로**, 카피를 처음 보는 독자 입장에서 읽는다
3. `python scripts/review.py <폴더> --validate` → review.json 완결성 확인 + 최종 판정 출력
4. 판정이 `수정 필요`면 카피 단계로 돌려 copy.json 고친 뒤 1번부터 다시(round +1). `통과`여야 승인 단계로 간다.

## 체크리스트
A. **사실 대응** — 본문·제목·표지·카드의 모든 사실 문장을 factsheet 항목(또는 pack 출처)에 연결. 연결 안 되면 오류.
B. **의미 왜곡** — 사실은 맞지만 독자가 잘못 이해할 표현. 특히 시점("하루 만에"/"같은 날"), 범위("혼자 다 된다" ↔ 국회 소추만 단독 가능), 단계(당론 ↔ 발의 ↔ 의결 ↔ 파면), 주어(누가 말했나), 소속·직함이 출처에 실제로 있는지.
C. **인용 맥락** — 인용이 원래 맥락과 같은 뜻으로 쓰였나. 축약으로 뜻이 바뀌지 않았나.
D. **상대측 입장** — 한 문장 이상, 왜곡 없이 들어갔나.
E. **법적 위험** — 명예훼손(실명 인물에 대한 허위 사실·범죄 단정), 모욕(비하·욕설), 사생활. 공인 비판은 '공적 행위 + 사실 근거 + 의견 표시'면 허용.
F. **플랫폼 정책** — 혐오·괴롭힘·집단 비하 없음. 비하 별명 없음.
G. **표지·카드 단독 읽기** — 표지·카드만 본 사람이 오해할 문장이 없나(본문 맥락 없이도 사실이어야 함).

## 심각도
- `치명`: 허위 사실, 지어낸 인용, 법적 위험 → 판정 `게시 불가`
- `중요`: 의미 왜곡, 출처에 없는 소속·수치, 오해 유발 표지 → 판정 `수정 필요`
- `경미`: 표현 다듬기, 근거가 1곳뿐인 수치 → 수정 권고(판정에 영향 없음)

## review.json 형식
```json
{
  "issue": "...",
  "round": 1,
  "reviewed_at": "ISO 시각",
  "machine_checks": {"factsheet": "통과|실패", "copy": "통과|실패", "risk_lint": "경고 N건"},
  "sentence_map": [{"id": "B1", "text": "본문 문장", "refs": ["facts[1]"], "kind": "사실|의견|전환"}],
  "findings": [{"severity": "치명|중요|경미", "where": "cover.options[2].line1", "category": "A~G",
                "problem": "...", "fix": "구체적 수정안"}],
  "verdict": "통과|수정 필요|게시 불가",
  "summary": "한두 문장"
}
```
`sentence_map`은 review_input.md의 문장 ID(B·T·C·S)를 빠짐없이 덮어야 한다.
